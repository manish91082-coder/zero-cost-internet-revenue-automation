## 1. Scope and non-negotiable rule
This batch audits the platform usage and operating cost stack for a hypothetical Apify Store Actor. It is a model, not a test. No account, Actor, paid plan, test run, customer run, listing or payout was created or executed. No costs were incurred.
A route passes Gate 3 only if all development, test, customer execution, platform, payout, support, refund, monitoring, maintenance and compliance costs can be covered without owner-funded expenditure under the project's ₹0 rule. A promotional credit or temporary free allowance is not evidence of sustainably free commercial operations.

## 3. Creator revenue and usage-cost mechanics
Current Apify Store publishing terms state creator payout is 80% of user-paid Actor fees minus platform usage costs for corresponding runs, as configured. The remaining 20% belongs to Apify. Platform usage costs include compute, proxies, data transfer and storage operations.
Official source: https://docs.apify.com/legal/store-publishing-terms-and-conditions

Apify's pricing-and-costs documentation provides the pay-per-event profit formula:
profit = (0.8 × event revenue) − platform costs.
It further says only revenue and costs generated by users on paid plans count toward this calculation; free-plan users do not generate creator revenue and Apify covers their platform usage costs.
Official source: https://docs.apify.com/actors/monetize/pricing-and-costs

Important pricing-model distinction:
- Pay-per-event (PPE): user is charged for defined events. The creator's 80% share is reduced by relevant platform usage costs. If pricing is too low relative to resource use, creator profit can be negative.
- Pay-per-usage: customer pays platform usage, but a multi-tenant Server Actor runs in the creator's account and platform usage for paid users is deducted from creator payout.
- Monthly rental: payout and platform usage treatment depend on the current Store terms/configuration; do not assume rental revenue is cost-free.
- A free user or promotional-credit user does not automatically create monetizable earnings. Current publishing terms state promotional-user payout is calculated by configured discount-tier rules; exact effective net must be checked per configuration.
Official sources: https://docs.apify.com/actors/monetize ; https://docs.apify.com/actors/monetize/set-up-monetization ; https://docs.apify.com/legal/store-publishing-terms-and-conditions

## 4. Illustrative compute-only unit economics
These examples are mathematical sensitivities, not measured Actor performance. They exclude proxies, data transfer, storage, refunds, payout fees, tax, support and maintenance. USD is used because Apify publishes prices in USD. They are not revenue forecasts.

| PPE event price | 80% creator share | Compute usage | Compute cost | Remainder before all other costs |
|---:|---:|---:|---:|---:|
| $1.00 | $0.80 | 1 CU | $0.20 | $0.60 |
| $1.00 | $0.80 | 4 CU | $0.80 | $0.00 |
| $1.00 | $0.80 | 5 CU | $1.00 | -$0.20 |
| $2.00 | $1.60 | 4 CU | $0.80 | $0.80 |
| $2.00 | $1.60 | 8 CU | $1.60 | $0.00 |

At $1 PPE event price, compute-only break-even is 4 CU, before every other cost. If an event uses 1 GB residential proxy, the proxy alone costs $8, far exceeding the $0.80 creator share at a $1 event. Thus proxy-heavy scraping is not a ₹0-cost design and requires customer pricing that fully covers resources, while still retaining positive net proceeds.
Source unit rates: https://docs.apify.com/actors/monetize/pricing-and-costs

## 6. ₹0 design envelope — what might remain feasible?
Potentially lower-cost Actor types for later research (not product approval):
- Pure deterministic data transformation over user-supplied small files, with no external scraping, no paid model calls, minimal compute, minimal persistence.
- Static validation/conversion utilities that return results within one short run and avoid proxies.
- Tools that use customer-provided credentials/resources only where platform terms permit and security obligations can be met; do not store secrets unnecessarily.
Even these are not proven ₹0: Apify platform usage is metered, customer free-tier usage and promotional users need separate treatment, payout costs remain, and human maintenance/support still exists.

High-risk / likely incompatible with strict ₹0:
- Residential-proxy scraping, SERP scraping, high-volume browser automation.
- LLM-heavy agents with external paid inference.
- Multi-tenant long-running server Actors whose resource costs are deducted from creator payout.
- High-frequency monitoring, persistent storage, large datasets, large file processing and guaranteed SLAs.
- Products requiring external hosting, domains, email/SMS, telephony, paid monitoring or customer support labor.
